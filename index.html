Limit Order Book Matching Engine

2026 · Individual project · C++20

A price-time priority matching engine modeled on how real exchanges work, built to be fast and to stay memory safe while doing it.

  • C++20
  • CMake
  • ASan
  • UBSan
  • Custom allocators
Technical details
  • Cancels an order in constant time by caching real std::map iterators in a custom LevelHandle union, which avoids a logarithmic re-descent into the book.
  • Wrote MemoryPool<T>, a slab allocator with an intrusive free list. Allocation took 1.0 ns against 20.5 ns for std::list.
  • Replaced 8-byte pointers with 4-byte pool indices in an intrusive doubly linked order queue, lifting throughput from about 8.8M to 9.56M orders per second.
  • Prices are int64 ticks, never floating point, so rounding error cannot creep into matching.
  • Found that the compiler was eliminating dead code in a micro-benchmark, then replaced it with a high-churn traversal that measures real work.

AI Size & Fit Recommender

2026 · Individual project · Python, scikit-learn, FastAPI

Predicts whether a clothing size will fit, small or large, to cut the returns that come from sizes that vary between brands. Built from raw data to a live web app.

  • Python
  • scikit-learn
  • pandas
  • FastAPI
  • Streamlit
Technical details
  • Trained a 300-tree Random Forest on the RentTheRunway dataset: 192K transactions, 105K users and 5.8K items.
  • Reached 0.5088 macro-F1 against a 0.2831 baseline, a 79.7% gain. Macro-F1 is the target because 73.8% of rows are "fit", which makes accuracy misleading.
  • Split by user with GroupShuffleSplit so no person appears in both train and test, and used balanced class weights for the imbalance.
  • Engineered 18 features. The strongest was size_delta, the distance from an item's typical fitting size, which showed that item history predicts fit better than body measurements.
  • Served predictions through a FastAPI backend and deployed a Streamlit Cloud app that returns a ranked size with confidence.

Elastic Face Recognition: IaaS to Serverless to Edge

Fall 2025 · CSE 546 Cloud Computing, ASU · Individual · Python, AWS

One face recognition pipeline rebuilt three ways to compare how each cloud model behaves.

  • AWS EC2
  • S3
  • SQS
  • Lambda
  • IoT Greengrass
  • MQTT
  • PyTorch
Technical details
  • IaaS. A three-tier app on raw EC2, S3 and SQS. I wrote the autoscaler myself instead of using AWS Auto Scaling, and it scales the app tier from 0 to 15 instances from live queue depth, scaling in right away when idle.
  • Serverless. Moved the pipeline to AWS Lambda, chaining MTCNN face detection and FaceNet recognition (PyTorch) through SQS. It completed every request with an average latency under three seconds.
  • Edge. Ran AWS IoT Greengrass on an EC2 instance as an emulated gateway. Detection runs locally and talks over MQTT, while recognition stays in Lambda.

BabyCam

Dec 2023 – Apr 2024 · Internship project at Escrow Infotech · Individual · Kotlin, Android

An Android app that turns two phones into a baby monitor with no router in between. One phone is the camera, the other is the parent's monitor.

  • Kotlin
  • Jetpack Compose
  • MVVM
  • Wi-Fi Direct
  • UDP sockets
  • Android Studio
Technical details
  • Connected the devices peer to peer over Wi-Fi Direct, with a discovery manager that lets the parent phone scan for the camera phone and connect to it.
  • Streamed live video over continuous UDP socket communication, converting frames to byte arrays and displaying them as bitmaps.
  • Let the parent phone record the live feed to internal storage through the Android Storage APIs.
  • Structured the app with MVVM and Jetpack Compose, and handled camera, location and storage permissions with error handling for denied requests.
  • Designed a clean server shutdown so disconnecting never crashes the app.
